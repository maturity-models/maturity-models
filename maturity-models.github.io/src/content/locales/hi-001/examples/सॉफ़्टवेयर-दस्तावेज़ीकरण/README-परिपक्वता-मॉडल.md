# README परिपक्वता मॉडल

## स्तर एक: "कोड ही दस्तावेज़ है"

- किसी भी प्रकार का README पाठ नहीं है/लगभग नहीं है।
- कोई स्थापना, कॉन्फ़िगरेशन, चलाने का विवरण नहीं।
- कोई डेवलपर दस्तावेज़ीकरण नहीं।
- कोई पूरक फ़ाइलें नहीं, जैसे योगदानकर्ता दिशानिर्देश।
- कोई बिल्ड स्थिति की जानकारी नहीं, इसलिए परियोजना की वर्तमान स्थिति की कोई झलक नहीं।
- मुद्दों और/या पुल रिक्वेस्ट के लिए कोई सुझाया गया औसत प्रतिक्रिया समय नहीं।
- कोड कवरेज या अन्य गुणवत्ता मापदंड दिखाने वाले कोई बैज नहीं।
- जो भी पाठ उपलब्ध है वह अप्रचलित या गैर-प्राथमिकता वाला हो सकता है।

**अनुशंसा**: कभी-कभी डेवलपर ऐसी व्यक्तिगत परियोजनाएँ और प्रयोग पोस्ट करते हैं जो साझा करने के लिए तैयार नहीं होते। ऐसे मामलों में कम या कोई दस्तावेज़ीकरण न होना स्वीकार्य हो सकता है। हम अनुशंसा करते हैं कि README परियोजना की प्रकृति/स्थिति बताए। उदाहरण के लिए, उपयोगकर्ताओं को चेताएँ कि "यह परियोजना प्रयोगात्मक/व्यक्तिगत है, इसलिए अपने जोखिम पर उपयोग करें।"

## स्तर दो: न्यूनतम README

- परियोजना की कार्यक्षमता और उद्देश्य के बारे में सीमित जानकारी।
- उपयोगकर्ताओं के लिए बुनियादी स्थापना, कॉन्फ़िगरेशन, चलाने का विवरण, पर अपरीक्षित और अपूर्ण।
- बुनियादी या कोई डेवलपर दस्तावेज़ीकरण नहीं।
- README में योगदान के बारे में एक पंक्ति, पर कोई समर्पित फ़ाइल नहीं।
- परियोजना की बिल्ड स्थिति के बारे में एक पंक्ति, हालाँकि वह अप्रचलित हो सकती है; या कोई बिल्ड स्थिति जानकारी नहीं।
- मुद्दों और/या पुल रिक्वेस्ट के औसत प्रतिक्रिया समय के बारे में एक पंक्ति।
- कोड कवरेज या अन्य गुणवत्ता मापदंड दिखाने वाले कोई बैज नहीं।
- पाठ शायद ही कभी अद्यतन किया जाता है और अप्रचलित या अशुद्ध हो सकता है।

**अनुशंसा**: स्तर दो का README व्यापक पाठकों को लक्षित करता है, पर उसकी अपूर्णता निराशा और व्यर्थ प्रयास का कारण बनती है। कभी-कभी यह कोई दस्तावेज़ीकरण न होने से भी बुरा होता है। एक टिप्पणी शामिल करें जो बताए कि परियोजना प्रारंभिक चरण की, अस्थिर, प्रयोगात्मक या व्यक्तिगत है या नहीं।

## स्तर तीन: बुनियादी README

- परियोजना की कार्यक्षमता, उपयोगिता और उद्देश्य के बारे में कुछ विस्तृत जानकारी।
- उपयोगकर्ताओं के लिए बुनियादी स्थापना, कॉन्फ़िगरेशन, चलाने का विवरण, परीक्षित और पूर्ण।
- संभावित योगदानकर्ताओं के लिए बुनियादी दस्तावेज़ीकरण।
- नए योगदानकर्ताओं को जोड़ने के लिए एक दृष्टि कथन या परियोजना रोडमैप।
- बुनियादी जानकारी वाली Contributing.md/.rst फ़ाइल।
- परियोजना की बिल्ड स्थिति के बारे में एक पंक्ति, पर न्यूनतम: "विकासाधीन" या "स्थिर।"
- मुद्दों और/या पुल रिक्वेस्ट के औसत प्रतिक्रिया समय के बारे में एक पंक्ति।
- कोड कवरेज या अन्य गुणवत्ता मापदंड दिखाने वाला कम से कम एक बैज।
- पाठ मासिक या त्रैमासिक अंतराल पर अद्यतन किया जाता है, इसलिए अशुद्धियाँ हो सकती हैं।

**अनुशंसा**: स्तर तीन का README छोटे पैमाने पर समुदाय की वृद्धि को सहारा देने के लिए पर्याप्त संपूर्ण है। योगदानकर्ता विकास की ज़रूरत वाली प्रारंभिक चरण की परियोजनाओं को प्रकाशन से पहले इस स्तर तक पहुँचने का लक्ष्य रखना चाहिए। परियोजना का व्यापक रूप से अपनाया जाना संभव है, हालाँकि README बाधाएँ उत्पन्न कर सकता है।

- परियोजना के उद्देश्य, कार्यक्षमता और विशेष सुविधाओं/गुणों के बारे में विस्तृत जानकारी, ताकि पाठक उसकी सुविधाओं और गुणों की उपयोगिता और प्रभाव को तुरंत समझ सके।
- उपयोगकर्ता प्रशंसापत्र और वास्तविक विकास परिस्थितियों में पिछले प्रदर्शन के प्रमाण।
- विस्तृत उपयोगकर्ता स्थापना, कॉन्फ़िगरेशन और चलाने के निर्देश, परीक्षित और वर्तमान; सामान्य त्रुटियों और उनके समाधान के बारे में जानकारी।
- संभावित योगदानकर्ताओं के लिए विस्तृत दस्तावेज़ीकरण।
- नए योगदानकर्ताओं को जोड़ने के लिए विस्तृत दृष्टि कथन या परियोजना रोडमैप।
- अंतर्निहित दृश्य सहायता जैसे आरेख और डेमो।
- विस्तृत शैली-दिशानिर्देशों वाली Contributing.md/.rst फ़ाइल।
- बिल्ड स्थिति परियोजना के उन विशिष्ट पहलुओं की पहचान करती है जो अपूर्ण हैं और/या अस्थिरता पैदा कर रहे हैं।
- मुद्दों और/या पुल रिक्वेस्ट के औसत प्रतिक्रिया समय के बारे में स्पष्ट जानकारी।
- कोड कवरेज या अन्य गुणवत्ता मापदंड दिखाने वाले एक या अधिक बैज।
- पाठ साप्ताहिक या दैनिक अंतराल पर भी अद्यतन किया जाता है, इसलिए अशुद्धियों की संभावना कम है।

**अनुशंसा**: स्तर पाँच के README आमतौर पर व्यापक योगदानकर्ता/उपयोगकर्ता आधार वाली परियोजनाओं से उभरते हैं। उनका विवरण उत्पादन-तैयार उपयोग और पर्यवेक्षित योगदान को सुदृढ़ करता है। हर परियोजना को इस स्तर के दस्तावेज़ीकरण की आकांक्षा रखनी चाहिए।
