# 程序员能力矩阵

出处：http://sijinjoseph.com/programmer-competency-matrix/

此列表已根据我们团队的偏好进行了改编和编辑。


## 计算机科学

数据结构：

1. 能够在实际编程任务中解释和使用数组、链表、字典等

2. 了解基本数据结构的空间与时间权衡、数组与链表的对比，能够解释哈希表如何实现及如何处理冲突、优先队列及其实现方式等。

3. 了解高级数据结构，如 B 树、二项堆和斐波那契堆、AVL 树/红黑树、伸展树、跳表、字典树等。

算法：

1. 基本的排序、搜索，以及数据结构遍历和检索算法

2. 树、图、简单的贪心以及分治算法，能够理解此矩阵各级别的相关性。

3. 能够识别并编写动态规划解决方案，对图算法有良好了解，对数值计算算法有良好了解，能够识别 NP 问题等。

系统编程：

1. 对编译器、链接器和解释器有基本了解。理解汇编代码是什么，以及硬件层面的工作方式。对虚拟内存和分页有一定了解。

2. 理解内核态与用户态、多线程、同步原语及其实现方式，能够阅读汇编代码。理解网络如何工作，了解网络协议和套接字级编程。

3. 理解整个编程栈：硬件（CPU + 内存 + 缓存 + 中断 + 微码）、二进制代码、汇编、静态与动态链接、编译、解释、JIT 编译、垃圾回收、堆、栈、内存寻址。


## 软件工程

源代码版本控制的使用：

1. 初学用户，能够克隆、推送、拉取等。

2. 中级，能够变基、使用生态系统工具（如别名、插件、钩子）、使用各种版本管理流程等。

3. 高级，例如能够创建生态系统工具（如编写别名、插件、钩子）。

构建自动化：

1. 知道如何从命令行构建系统

2. 能够设置脚本来构建基本系统

3. 能够设置脚本来构建系统，同时构建文档、安装程序、生成发布说明并在源代码控制中给代码打标签

自动化测试：

1. 编写过自动化单元测试，并能为正在编写的代码想出良好的单元测试用例

2. 以 TDD 方式编写过代码

3. 理解并能够设置自动化功能测试、负载/性能测试和 UI 测试


## 编程

问题分解：

1. 能够把问题拆分成多个函数

2. 能够想出可复用的函数/对象来解决整体问题

3. 使用合适的数据结构和算法，并想出通用的/面向对象的代码，封装问题中易变的方面。

系统分解：

1. 只要在同一平台/技术内，就能够拆分问题空间并设计解决方案

2. 能够设计跨多种技术/平台的系统。

3. 能够设想并设计具有多条产品线以及与外部系统集成的复杂系统。还应该能够设计运维支持系统，如监控、报告、故障切换等。

沟通：

1. 同行能够理解所说的话。拼写和语法良好。

2. 能够与同行有效沟通

3. 能够以明确无歧义的方式理解和传达想法/设计/创意/规格说明，并根据情境调整沟通方式


## 代码质量

文件内的代码组织：

1. 方法按逻辑或访问级别分组

2. 代码被分组到区域中，并有良好的注释，并引用其他源文件

3. 文件有许可证头、摘要、良好的注释、一致的空白使用。文件应该看起来很漂亮。

跨文件的代码组织：

1. 相关文件被归入一个文件夹

2. 每个物理文件都有唯一的用途，例如一个类定义、一个功能实现等。

3. 物理层面的代码组织与设计紧密匹配，查看文件名和文件夹分布就能洞察设计

源代码树组织：

1. 将代码基本划分到逻辑文件夹中。

2. 没有循环依赖，二进制文件、库、文档、构建产物、第三方代码都组织到适当的文件夹中

3. 源代码树的物理布局与逻辑层次和组织相匹配。目录名称和组织让人能洞察系统的设计。

代码可读性：

1. 文件、变量、类、方法等命名良好。

2. 没有冗长的函数，有注释解释不寻常的代码、缺陷修复、代码假设

3. 使用断言验证代码假设，代码流程自然 &#8211; 条件或方法没有深层嵌套

防御式编码：

1. 检查参数并在代码中断言关键假设

2. 确保检查返回值，并对可能失败的代码周围检查异常。

3. 拥有自己的库来辅助防御式编码，编写模拟故障的单元测试

错误处理：

1. 对可能抛出异常/产生错误的代码做基本的错误处理

2. 确保错误/异常使程序保持良好状态，资源、连接和内存都被妥善清理

3. 编码以提前检测可能的异常，在各层代码中保持一致的异常处理策略，为整个系统制定异常处理指南。


## 工具

IDE：

* 熟悉界面，能够通过菜单有效地使用 IDE。

* 了解最常用操作的键盘快捷键。

* 编写过自定义宏

API：

1. 记得常用的 API

2. 对 API 有广泛而深入的了解

3. 编写过位于 API 之上的库，以简化常用任务并弥补 API 的不足


框架：

1. 听说过但没有使用过该平台上可用的流行框架。

2. 在专业场合使用过多个框架，并且熟悉这些框架的惯用法。

3. 框架的作者

需求：

1. 接收给定的需求并按规格编码，能够就遗漏的情况提出问题

2. 理解全貌，并想出需要制定规格的整个领域

3. 能够基于经验，对给定需求提出更好的备选方案和流程

脚本：

1. 批处理文件/shell 脚本

2. Perl/Python/Ruby/VBScript/Powershell

3. 编写并发布过可复用的代码

数据库：

1. 了解基本的数据库概念、规范化、ACID、事务，并能编写简单的 select 查询

2. 能够设计良好的、规范化的数据库模式，同时考虑到必须运行的查询，熟练使用视图、存储过程、触发器和用户定义类型。了解聚集索引和非聚集索引的区别。熟练使用 ORM 工具。

3. 能够做基本的数据库管理、性能优化、索引优化，编写高级的 select 查询，能够用关系型 SQL 取代游标的使用，理解数据在内部是如何存储的，理解索引在内部是如何存储的，理解数据库如何镜像、复制等。理解两阶段提交如何工作。


## 经验

具有专业经验的语言：

1. 命令式、面向对象和声明式（SQL），如果理解静态类型与动态类型、弱类型与强类型以及静态推断类型，则有额外加分

2. 函数式，如果理解惰性求值、柯里化、延续，则有额外加分

3. 并发式（Erlang、Elixir、Oz）和逻辑式（Prolog）

具有专业经验的平台：

1. 大约 1 年

2. 大约 5 年

3. 大约 10 年以上

专业经验年限：

1. 大约 1 年

2. 大约 5 年

3. 大约 10 年以上

领域知识：

1. 在该领域至少参与过一个产品的工作。

2. 在同一领域参与过多个产品的工作。

3. 领域专家。在该领域设计并实现过多个产品/解决方案。熟悉该领域使用的标准术语、协议。


## 知识

工具知识：

1. 了解流行和标准的工具，最好还了解一些替代品。

2. 对编辑器、调试器、IDE、开源替代品等有良好的了解。例如，了解 Scott Hanselman 强力工具列表中大部分工具的人。使用过 ORM 工具。

3. 实际编写过工具和脚本，如果已发布则有额外加分。

对新兴技术的了解：

1. 听说过该领域的新兴技术

2. 下载过 alpha 预览版/CTP/beta 版，并阅读过一些文章/手册

3. 试用过预览版并确实用它构建了某样东西，作为加分项还与大家分享了

平台内部机制：

1. 对平台内部如何工作有基本了解

2. 对平台内部机制有深入了解，能够设想平台如何接收程序并将其转换为可执行代码。

3. 编写过增强平台内部机制或提供其信息的工具。例如反汇编器、反编译器、调试器等。

书籍：

1. 《Code Complete》《Don't Make me Think》《Mastering Regular Expressions》

2. 《Design Patterns》《Peopleware》《Programming Pearls》《Algorithm Design Manual》《Pragmatic Programmer》《Mythical Man month》

3. 《Structure and Interpretation of Computer Programs》《Concepts Techniques, Models of Computer Programming》《Art of Computer Programming》《Database systems》（C. J Date 著）《Thinking Forth》《Little Schemer》

博客：

1. 阅读技术/编程/软件工程博客，收听播客等。

2. 维护一个链接博客，收集一些他/她所搜集的有用文章和工具

3. 维护一个博客，在其中分享个人对编程的见解和想法
