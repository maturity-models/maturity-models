# Xebia 数据中心自动化成熟度模型

出处：https://www.xebia.com/datacenter-automation

<table>

<tr>
<th>领域</th>
<th>0 级<br>未开始</th>
<th>1 级<br>初学者</th>
<th>2 级<br>基础</th>
<th>3 级<br>中级</th>
<th>4 级<br>高级</th>
<th>5 级<br>专家</th>
</tr>

<tr>
<th>安全与合规</th>
<td>围绕合规的安全没有正式流程。</td>
<td>定期对操作系统软件包进行补丁轮换。</td>
<td>没有共享账户。策略已定义。组件保持最新。</td>
<td>完整的审计轨迹；定期验证策略。</td>
<td>完全自动化的安全与合规检查。</td>
<td>对安全与合规风险有完整洞察并能完全掌控。</td>
</tr>

<tr>
<th>运营管理</th>
<td>系统容量耗尽后才订购新硬件。</td>
<td>请求更多容量时才订购新硬件；硬件专属于项目。</td>
<td>硬件容量在项目之间共享。</td>
<td>定期检查可用容量和已用容量。</td>
<td>按使用量分摊成本；检测未充分利用的组件。</td>
<td>对容量、成本、业务价值和运营负担有完全自动化的洞察。</td>
</tr>

<tr>
<th>韧性</th>
<td>存在多个单点故障；靠手动修复。</td>
<td>定期验证备份/恢复流程。</td>
<td>关键组件有冗余。</td>
<td>所有组件都有冗余。备份/恢复流程已自动化并经常验证。</td>
<td>自愈。</td>
<td>有计划和无计划的自动化韧性测试；预测性自动伸缩。</td>
</tr>

<tr>
<th>可观测性</th>
<td>没有监控和日志；最终用户最先发现停机。</td>
<td>通过运维提供日志。对平台组件进行基本监控。</td>
<td>通过仪表板提供监控。告警发送给集中的运维团队。</td>
<td>每个产品团队都可以通过自助服务获取日志。</td>
<td>产品团队可配置告警和自定义仪表板。</td>
<td>自定义指标。产品团队根据自定义事件配置告警。</td>
</tr>

<tr>
<th>供给</th>
<td>没有流程，没有自动化；所有变更都手动执行，并依据操作员的个人见解。</td>
<td>标准化流程；基本脚本。</td>
<td>使用标准配置管理工具进行供给。</td>
<td>没有手动变更；完整的配置管理。</td>
<td>不可变基础设施。</td>
<td>基础设施即代码。</td>
</tr>

<tr>
<th>数据中心交付</th>
<td>没有工具；没有文档。</td>
<td>标准化流程；人员经过培训后执行。</td>
<td>变更在应用前经过实验室测试。</td>
<td>以小迭代交付功能。</td>
<td>大多数组件有自动化测试。</td>
<td>所有基础设施组件持续交付。</td>
</tr>

<tr>
<th>生产团队自主性</th>
<td>没有正式流程；通过运维提出请求并期待最终交付。</td>
<td>标准化的请求表单，等运维有空时才处理。</td>
<td>标准化请求；在两周内完成。</td>
<td>基本功能的部分自助服务。</td>
<td>带图形用户界面的自助服务门户。</td>
<td>带图形用户界面和 API 的完整自助服务。</td>
</tr>

</table>
