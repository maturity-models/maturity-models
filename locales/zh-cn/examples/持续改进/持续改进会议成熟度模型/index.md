# 持续改进会议成熟度模型

持续改进会议，又称回顾会议，帮助团队随着时间推移不断进步。

<table>

<tr>
<th></th>
<th>0 级<br>无、<br>可忽略、<br>不适用</th>
<th>1 级<br>起步、<br>非正式、<br>不规律</th>
<th>2 级<br>发展、<br>描述、<br>复制</th>
<th>3 级<br>标准化、<br>明确规定、<br>面向服务</th>
<th>4 级<br>管理、<br>度量、<br>面向使命</th>
<th>5 级<br>优化、<br>编排、<br>面向机遇</th>
</tr>

<tr>
<th>频率</th>
<td>可忽略。</td>
<td>临时性的，很少举行。</td>
<td>每 12 周或每季度一次，或更久，例如仅在项目结束时进行。</td>
<td>每 4 周或每月一次。</td>
<td>每 2 周一次。</td>
<td>每周一次，同时也按需、即时举行。</td>
</tr>

<tr>
<th>典型议题</th>
<td>不适用。</td>
<td>通常围绕眼前的痛点。</td>
<td>通常讨论/描述模式和实践。</td>
<td>主要与服务相关的需求有关。</td>
<td>主要直接与指标、度量和管理相关。</td>
<td>完全与全组织范围的机遇和持续优化相关。</td>
</tr>

<tr>
<th>示例事项</th>
<td>不适用。</td>
<td>缺陷、错过的截止日期、质量差。</td>
<td>根因分析。按领域对缺陷聚类。故障分析。代码质量指标。RAID 日志。</td>
<td>如何提供更好的服务。如何改进速度、可靠性、安全性等系统质量属性。不问责的回顾。五问法（5-why）。</td>
<td>客户反馈领域、是否适用于目的、业务价值，以及与 OKR、KPI、仪表板和分析相关的领域。</td>
<td>将团队解决方案产品化的优化路径；创建开源工具提供帮助；出版相关主题的书籍；邀请合作伙伴协助。</td>
</tr>

<tr>
<th>发言、行动和跟进的参与度</th>
<td>可忽略。</td>
<td>主要是一两位“英雄”团队成员。</td>
<td>低比例的团队成员。</td>
<td>中等比例的团队成员。</td>
<td>大多数团队成员参与，并共同承担责任。</td>
<td>所有团队成员积极参与，并共同承担责任和问责。</td>
</tr>

<tr>
<th>重点</th>
<td>无。</td>
<td>聚焦非正式和不规律的领域。</td>
<td>聚焦描述和记录。</td>
<td>聚焦服务。</td>
<td>聚焦使命。</td>
<td>聚焦机遇。</td>
</tr>

<tr>
<th>主持人</th>
<td>无。</td>
<td>团队中的一两位“英雄”。</td>
<td>一两位团队负责人，例如经理、老板、资深人员。</td>
<td>共同领导，例如每位队友轮流担任。</td>
<td>不在团队中的外部主持人。他们具有主持此类会议的专门经验，并接受过专门培训。</td>
<td>持续有多位不在团队中的外部主持人。他们在整个组织和/或行业中工作。他们在持续改进方面具有专门经验，例如多种形式和风格。他们接受过专门培训，例如关键沟通、非暴力沟通、包容性、多样性等。</td>
</tr>

</table>
