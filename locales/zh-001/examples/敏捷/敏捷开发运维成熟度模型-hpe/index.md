<h2><a name="组织">组织</a></h2>

1. 初始

  * 开发团队孤立工作，使用他们认为最适合交付工作的工具、中间件和组件。

2. 受管理

  * 组织开始在开发中接受敏捷习惯。

  * 运维仍被视为独立的。

  * 各团队之间的一致性参差不齐。

3. 已定义

  * 实施有纪律的敏捷交付流程和实践。

  * 持续改进已就位。

  * 适当的治理已就位。

4. 已度量

  * 实践社区支持整个组织的敏捷习惯和高成熟度。

  * 已有度量系统来跟踪交付的业务价值。

  * 识别低效之处并采取行动。

5. 优化

  * 精益和敏捷是组织文化的一部分。

  * 持续学习并优化工作流程。


<h2><a name="团队合作">团队合作</a></h2>

1. 初始

  * 团队合作差，沟通与协调临时应付。

  * 没有知识库。

  * 很少分享。

  * 成功主要靠个人的英雄式努力。

2. 受管理

  * 一些知识共享活动开始启动。

  * 团队开始在开发内部沟通。

  * 标准工作实践已定义并大多得到遵循。

3. 已定义

  * 同地办公的开发、测试和运维团队开始朝着共同目标一起工作。

  * 在整个供应链中启动沟通和反馈环。

4. 已度量

  * 实现开发团队、测试团队和运维团队之间的整合，甚至跨多个国家的团队也是如此。

  * 庆祝成功。

  * 员工的贡献得到充分尊重和认可。

5. 优化

  * 有效的知识共享。

  * 个人赋权。


<h2><a name="构建管理与持续集成">构建管理与持续集成</a></h2>

1. 初始

  * 手动且被动的流程。

  * 很少管理制品、文档和源代码。

  * 失控。

2. 受管理

  * 在构建阶段和测试阶段实施了自动化，但仍然是孤岛式的。

  * 没有集中的基础设施。

3. 已定义

  * 每次提交源代码变更时，都会执行自动化的构建和测试循环。

  * 管理依赖项。

  * 脚本和工具可复用。

4. 已度量

  * 收集构建指标，使其可见，并据此采取行动。

  * 吸取经验教训。

  * 持续改进已就位。

5. 优化

  * 团队定期开会讨论集成问题。

  * 团队通过自动化、快速反馈和更高的可见性来解决问题。


<h2><a name="持续交付与部署">持续交付与部署</a></h2>

1. 初始

  * 手动部署软件，使用特定于环境的二进制文件。

  * 手动供给环境。

2. 受管理

  * 向部分环境部分自动化部署。

  * 部分环境可以自动供给。

  * 部分中间件和数据库组件由集中提供。

3. 已定义

  * 使用完全自动化的自助式流程部署软件。

  * 所有环境使用相同的部署流程。

4. 已度量

  * 部署经过编排和管理。

  * 发布流程经过测试。

  * 回滚流程经过测试。

5. 优化

  * 环境得到有效管理。

  * 供给完全自动化。

  * 常见组件有可用的标准拓扑。


<h2><a name="生命周期管理与合规">生命周期管理与合规</a></h2>

1. 初始

  * 发布不频繁且不可靠。

  * 手动的应用生命周期。

  * 软件质量结果参差不齐。

2. 受管理

  * 生命周期管理痛苦且不频繁，但发布可靠。

  * 从需求到发布的可追溯性有限。

  * 质量在提高。

3. 已定义

  * 精益的组合管理。

  * 变更管理和审批流程已就位并得到执行。

4. 已度量

  * 监控并主动管理环境健康和应用程序健康。

  * 监控周期时间。

5. 优化

  * 已有完整的组合和生命周期管理。

  * 管理整合了用户需求、开发、测试、预发布和生产。


<h2><a name="测试">测试</a></h2>

1. 初始

  * 手动测试。

  * 没有测试脚本。

  * 通常在开发之后才进行。

2. 受管理

  * 测试脚本和测试数据作为开发过程的一部分生成。

  * 测试脚本和测试数据用于自动化部分测试。

3. 已定义

  * 自动化单元测试。

  * 自动化验收测试。

  * 测试是开发过程的一部分。

  * 反馈环已就位。

  * 持续改进被度量和管理。

4. 已度量

  * 跟踪质量指标和趋势。

  * 定义并度量非功能性需求。

5. 优化

  * 测试完全自动化。

  * 生产环境回滚很少见。

  * 缺陷被立即发现并修复。


<h2><a name="数据与集成管理">数据与集成管理</a></h2>

1. 初始

  * 数据迁移手动执行。

  * 集成是临时性的，通常是点对点。

2. 受管理

  * 数据库变更通过使用与应用程序关联版本的自动化脚本完成。

  * 实施企业应用集成总线以便于集成。

3. 已定义

  * 数据库和集成包含在部署流程中。

4. 已度量

  * 每次部署都测试数据库升级和回滚。

  * 监控并优化数据库性能。

  * 使用消息队列执行集成，使其可以扩容和缩容。

5. 优化

  * 数据库和集成性能及部署流程在各个发布之间形成反馈环。
