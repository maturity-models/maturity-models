# 基于 CMMI CM SEI 的企业架构成熟度模型

此企业架构成熟度模型基于卡内基梅隆软件工程研究所（CM SEI）的软件能力成熟度模型集成（CMMI）。

参见 http://iea.wikidot.com/ea-maturity-model


<h2>0 级：无</h2>

* 没有企业架构计划。
* 谈不上有什么企业架构。


<h2>1 级：初始</h2>

* 非正式的企业架构开发流程正在进行。
* 流程是临时性的、局部的。
* 已定义了一些企业架构流程。
* 在所有业务服务、信息、业务流程、应用或技术视角之间，没有统一的企业架构流程。
* 成功取决于个人的努力。
* 企业架构流程、文档和标准通过各种临时手段建立，且是局部的或非正式的。
* 与业务战略或业务驱动因素的联系极少，或是隐含的。
* 管理团队对企业架构流程的认知或参与有限。
* 组织单元对企业架构流程的接受程度有限。
* 企业架构文档的最新版本在网络上。
* 关于企业架构流程及可能的流程改进，沟通极少。
* IT 安全方面的考虑是临时性的、局部的。
* 对架构标准没有明确的治理。
* 战略规划和采购人员很少或没有参与企业架构流程。
* 很少或根本不遵守现有标准。


<h2>2 级：开发中</h2>

* 企业架构流程正在开发中。
* 基本的企业架构流程。
* 企业架构流程已制定出清晰的角色和职责。
* 已识别愿景、原则、目标运营模型、当前基线和目标企业架构模型。
* 存在架构标准，但不一定与目标企业架构关联。
* 已建立参考架构模型。
* 与业务战略和 IT 战略有明确的联系。
* 管理层了解企业架构工作。
* 已分配职责，工作正在进行。
* 企业架构网页定期更新，并用于记录企业架构交付成果。
* IT 安全架构已定义了清晰的角色和职责。
* 对少数企业架构标准进行治理，对现有标准有一定程度的遵守。
* 对 IT 投资和采购战略很少或没有正式的治理。
* 各组织单元表现出对现有标准的一定遵守。


<h2>3 级：已定义</h2>

* 已定义的企业架构，包括详细的书面指南和参考架构模型。
* 企业架构定义良好，并已传达给业务和 IT 人员。
* 企业架构流程基本上得到遵循。
* 差距分析和迁移计划已完成。
* 完全开发的参考架构模型和标准。
* 已识别企业目标和流程。
* 企业架构与资本规划和投资控制流程相整合。
* 高级管理团队了解并支持企业架构流程。
* 管理层积极支持企业架构标准。
* 大多数组织单元表示接受企业架构开发流程或积极参与其中。
* 架构文档在企业架构网页上定期更新和发布。
* IT 安全架构标准已完全开发，并与企业架构整合。
* 对大多数 IT 投资有明确的书面治理。
* 存在 IT 采购战略，并包含对企业架构的合规措施。
* 在确定项目组合时考虑成本效益。


<h2>4 级：受管理</h2>

* 受管理且被度量的企业架构流程。
* 企业架构流程是文化的一部分。
* 捕获与企业架构流程相关的质量指标。
* 企业架构文档按固定周期更新，以反映更新后的企业架构。
* 流程、信息、应用和技术架构视角由适当的标准定义。
* 根据收到的反馈和从更新后的企业架构中吸取的教训，调整资本规划和投资控制。
* 定期重新审视业务驱动因素。
* 高级管理团队直接参与企业架构评审流程。
* 整个组织接受并积极参与企业架构流程。
* 企业架构文档定期更新，并经常审查最新的企业架构发展和行业标准。
* 捕获与 IT 安全架构相关的绩效指标。
* 对所有 IT 投资有明确的治理。
* 管理偏差的正式流程反馈到企业架构。
* 所有计划中的 IT 采购和购买均由企业架构指导和治理。


<h2>5 级：已度量并优化</h2>

* 企业架构流程的持续改进
* 协调一致地努力优化并持续改进企业架构流程。
* 使用标准与豁免流程来改进企业架构开发流程。
* 使用架构流程指标来优化并推动业务决策。
* 业务部门参与 IT 架构的持续流程改进。
* 高级管理层参与优化企业架构开发和治理中的流程改进。
* 使用所有组织单元对企业架构流程的反馈来推动企业架构流程的改进。
* 组织中的每一位决策者在做每项业务或 IT 决策时都使用企业架构文档。
* 使用来自 IT 安全架构指标的反馈来推动企业架构流程的改进。
* 对所有 IT 投资有明确的治理。
* 使用标准与豁免流程来改进治理流程的改进。
* 没有未经计划的 IT 投资或采购活动。
